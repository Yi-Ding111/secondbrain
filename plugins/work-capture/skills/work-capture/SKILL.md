# Work Capture

把**当前 AI thread 对话**整理成一份**可直接复制、自包含**的结构化记忆文案。

这是一个**独立工具**:它只做"对话 → 好文案"这一件事,**不知道、也不关心这份文案最后会被怎么用**。只依赖 thread 文本,不读代码库、不写任何文件。

> 分工:work-capture 抓**对话里的思路/问题/决策**;要**代码改动的流程图/数据流**,用同 plugin 的 `branch-review` skill(读 git diff)。本 skill **不画流程图**。

## When to use
- 一段 AI 对话(调试 / 设计 / 实现 / 思考)结束,想把"做了什么、怎么解决、关键决策"整理成一份能带走的记忆。
- 用户说 "work-capture" / "整理这次对话" / "生成记忆"。

## 记忆格式(自包含，规则内嵌于此)

产出是**记忆**,不是代码变更记录。git/diff 能存的不写;写 git 存不下的:逻辑、踩的坑、怎么解、为什么这么选。

**必含 5 段**(缺项写"本次无"):
1. **概述** — 目标 / 为什么 / 解决了什么(1-3 句)
2. **实现逻辑** — 做了什么、怎么做、为什么(prose,非文件清单)
3. **问题与方案** — 每个实质问题:现象 / 根因 / 走过的弯路 / 最终方案
4. **关键决策** — 取舍 + trade-off + 为什么
5. **回忆钩子** — 3-6 条"日后一眼想起"的抓手

**禁止**:文件/行号 diff、机械改动文件清单、逐 commit 流水账、Before-After 代码堆砌。若某几行代码是决策核心,可贴几行并解释**为什么重要**。

## Workflow

### Step 1 — 从 thread 抽取(不罗列改动)
通读当前对话,抽出:
- **解决了什么问题 / 目标**(→ 概述)
- **实现逻辑**:整体思路与方法
- **实质问题 → 根因 → 走过的弯路 → 最终方案**:对话里"卡住—尝试—失败—换法—通了"的地方就是金矿
- **关键决策 + trade-off**
琐碎报错、纯代码行不抽。代码改动 → 翻译成"做了什么/为什么"。

### Step 2 — 组装自包含 markdown
按 [[OUTPUT-FORMAT]](同 plugin 内 `../../OUTPUT-FORMAT.md`,work-capture 分支):frontmatter(`source: work-capture` + `title` / `date` / `topic` / `tags`,可选 `project`,**关联键 `ticket` / `branch` 有就填**)+ 5 段正文。

- **关联键(ticket / branch)**:填了能让下游把这份"对话记忆"和同任务的 `branch-review`"代码讲解"**互相链接**。
- **project / ticket** 只是可选元数据。ticket 只写编号,**不复制**其正文。
- 全部内容在**一个文件**里:无外部依赖、无 `[[link]]`——纯文本。

### Step 3 — 交付
把整份 markdown 作为**代码块**呈现给用户,方便一键复制。到此为止——文案交出去,怎么用是用户的事。

## 验收
拿一个真实 thread 跑 → 得到一份**可粘贴、无行号 diff、单独打开即完整可读**的记忆文案(5 段)。

## Anti-patterns
- ❌ 罗列"改了哪些文件/哪几行"
- ❌ 画流程图 —— 那是 `branch-review`(读代码)的事,本 skill 只讲对话里的逻辑/问题/决策
- ❌ 用 `[[wiki-link]]` 或假设某个知识库结构 —— 本文案要自包含、与下游无关
- ❌ 试图读代码库 / 写文件 —— 本 skill 只读 thread、只输出文本
- ❌ 替用户操心"这文案该归到哪"
